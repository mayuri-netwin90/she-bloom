# Module: App Users

## Module Overview

This module manages the administrative backoffice interface for viewing, filtering, inspecting, and managing She Bloom mobile application users, Bloom Club subscribers, and full dedicated user details with booking history, consent audits, and account actions (Requirements: `RF-BO-USR-01`, `RF-BO-USR-02`, `RF-BO-USR-03`, `RF-BO-USR-04`, `RF-BO-USR-05`).

---

## Module Responsibilities

* Display aggregate statistics of registered app users and Bloom Club subscribers
* Provide real-time searching across user names and email addresses
* Offer status-based filtering via pill tabs (All, Bloom Club, Free, Blocked)
* Render responsive tabular data for Desktop and Tablet screens with sorting and multi-row selection
* Provide a card-based fallback list for Mobile screens
* Present quick user information in a slide-out drawer
* Support full User Detail view (`AppUserDetail`) with profile information, account details, key-value attributes, consent audit log, activity tabs, and sensitive area controls
* Manage user bookings with semantic status badges (UPCOMING in blue, COMPLETED in green, CANCELLED in red) and single-line ellipsis truncation
* Provide tabbed activity inspection (Bookings with count badge, Payments, Reports, Access log) with strict bottom-line highlighting in brand violet 8 (`#3C2F58`)
* Support GDPR user data export and booking activity CSV export without outline borders
* Support user account suspension and permanent account anonymisation workflows via clean confirmation modals (`ActionModal`) matching Figma specifications
* Maintain strict design system adherence with zero hardcoded hex codes, primary brand pink styling, and semantic CSS tokens

---

## Key Entities

* AppUser (List summary: id, name, email, subscription, registeredOn, sessions, status)
* AppUserDetailData (Full detail: profile, contact, store, language, city, dateOfBirth, consents, bookings)

* AppUserSubscription (`club`, `free`)

## API Endpoints

GET /backoffice/users/app
Fetch paginated and filtered list of mobile app users
Authentication Required: Yes

GET /backoffice/users/app/:id
Fetch comprehensive profile, consents, and activity bookings for a specific mobile app user
Authentication Required: Yes

PATCH /backoffice/users/app/:id/status
Update user account status (e.g., active, blocked)
Authentication Required: Yes

POST /backoffice/users/app/:id/anonymize
Permanently anonymise user profile, personal data, and journals while retaining required statutory accounting data
Authentication Required: Yes

GET /backoffice/users/app/export
Download CSV export of app users matching filter criteria
Authentication Required: Yes

GET /backoffice/users/app/:id/bookings/export
Download CSV export of a specific user's bookings history
Authentication Required: Yes

GET /backoffice/users/app/:id/export-data
Export all GDPR personal data associated with the user
Authentication Required: Yes

## Main Workflows

App User Inspection and Filtering Flow

1. Administrator navigates to the App Users screen via the Management section of the sidebar.
2. The system displays the user list along with total counts of registered users and Bloom Club subscribers.
3. Administrator types into the search field or clicks a status pill (All, Bloom Club, Free, Blocked) to refine the table.
4. Administrator clicks on a table row or action icon to open the slide-out drawer containing detailed profile data and activity stats.

App User Dedicated Detail Flow

1. Administrator clicks the detail view icon in the table row or the "View full profile" action in the drawer.
2. The system renders the full `AppUserDetail` screen with breadcrumb navigation (`Management / App users / <User Name>`).
3. Left column presents user avatar (`72px`), name, email, subscription pill, registration details, key-value attributes (with labels at `44%` fixed width), and consent audit log.
4. Right column presents the Activity Tabs (Bookings with count badge, Payments, Reports, Access log) and Sensitive Area.
5. In Bookings table, column headers feature dropdown chevrons; service names render with single-line ellipsis truncation; status badges display semantic blue (UPCOMING), green (COMPLETED), and red (CANCELLED).

User Account Block Flow

1. Administrator initiates a block action via the Sensitive Area button (featuring the prohibited circle-slash icon) or mobile danger button.
2. The system opens the `ActionModal` (`size={460}`) confirming the action with primary text Cancel button and destructive Block user button.
3. Administrator confirms, updating user status to `blocked`.

Account Anonymisation Flow

1. Administrator clicks "Anonymise account" in the Sensitive Area.
2. The system displays a confirmation `ActionModal` (`size={460}`) warning of permanent data removal.
3. Administrator confirms, permanently anonymising personal records and updating account status to `anonymized`.

CSV and GDPR Export Flow

1. Administrator clicks "Export data (GDPR)" in the page header to download all user personal records.
2. Administrator clicks the borderless "Export CSV" action above the bookings table to export user session history.

## Security Considerations

* Only users with the `ADMIN` role can access the App Users management module and execute status or anonymisation actions.
* All state changes, GDPR exports, and CSV export requests require valid JWT backoffice authentication.
* Sensitive personal information such as password hashes must never be exposed to the client.
* Privacy by design: mobile app Journal content, Alba AI conversations, and emotional check-in reflections are strictly inaccessible from the backoffice interface.

---

## Important Business Rules

* Bloom Club subscribers are denoted with a dedicated violet badge indicator (`BLOOM CLUB`).
* Users in `blocked` status cannot log into the mobile app or access subscription services.
* Email addresses cannot be modified directly through the backoffice interface.
* In the App User Detail screen, active tabs must highlight only the bottom line (`borderBottom: '2px solid var(--brand-primary)'`) with active text styled in brand violet 8 (`#3C2F58`).
* Outline action buttons in the list view (Export CSV, More filters) use primary brand pink (`var(--brand-primary)`).
* In the detail view, the bookings "Export CSV" button is styled borderless with primary dark text (`var(--text-primary)`) and a bold download icon (`stroke={2.2}`).
* Account anonymisation is irreversible; statutory accounting records are retained while personal data and journals are purged.
