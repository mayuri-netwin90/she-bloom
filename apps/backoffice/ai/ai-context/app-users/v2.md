# Module: App Users

## Module Overview

This module manages the administrative backoffice interface for viewing, filtering, inspecting, and managing She Bloom mobile application users and Bloom Club subscribers (Requirements: `RF-BO-USR-01`).

---

## Module Responsibilities

* Display aggregate statistics of registered app users and Bloom Club subscribers
* Provide real-time searching across user names and email addresses
* Offer status-based filtering (All, Bloom Club, Free, Blocked)
* Render responsive tabular data for Desktop and Tablet screens with sorting and multi-row selection
* Provide a card-based fallback list for Mobile screens
* Present detailed user information in a slide-out drawer
* Support user account suspension and reactivation workflows via confirmation modals
* Export filtered app user records to CSV

---

## Key Entities

* AppUser
* AppUserSubscription (`club`, `free`)
* AppUserStatus (`active`, `blocked`, `to_verify`, `anonymized`)

---

## API Endpoints

GET /backoffice/users/app
Fetch paginated and filtered list of mobile app users
Authentication Required: Yes

GET /backoffice/users/app/:id
Fetch detailed profile and session metrics for a specific mobile app user
Authentication Required: Yes

PATCH /backoffice/users/app/:id/status
Update user account status (e.g., active, blocked)
Authentication Required: Yes

GET /backoffice/users/app/export
Download CSV export of app users matching filter criteria
Authentication Required: Yes

---

## Database Tables

mobile_users
Stores mobile app user credentials, profile information, and account status
Key Fields: id, email, name, password_hash, is_active, last_login_at, created_at, updated_at

## Main Workflows

App User Inspection and Filtering Flow

1. Administrator navigates to the App Users screen via the Management section of the sidebar.
2. The system displays the user list along with total counts of registered users and Bloom Club subscribers.
3. Administrator types into the search field or clicks a status pill (All, Bloom Club, Free, Blocked) to refine the table.
4. Administrator clicks on a table row or action icon to open the slide-out drawer containing detailed profile data and activity stats.

User Status Modification Flow

1. Administrator initiates a block/unblock action from the row actions menu or from within the user details drawer.
2. The system displays a confirmation modal with destructive or non-destructive styling based on the target state.
3. Administrator confirms the operation, the status change is processed, and the table updates accordingly.

---

## Security Considerations

Only users with the `ADMIN` role can access the App Users management module.
All state changes and CSV export requests require valid JWT backoffice authentication.
Sensitive information such as password hashes must never be exposed to the client.

---

## Important Business Rules

Bloom Club subscribers are denoted with a dedicated violet badge indicator.
Users in `blocked` status cannot log into the mobile app or access subscription services.
Email addresses cannot be modified directly through the quick edit drawer.
