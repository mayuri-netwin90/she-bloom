# Module: Mentor (Backoffice)

## Module Overview

The **Mentor** module provides the administrative backoffice interface to view, filter, verify, configure permissions for, and manage She Bloom Mentors (professionals including psychologists, nutritionists, dermatologists, personal trainers, and coaches) across their profile lifecycles, permissions, offerings, audios, schedules, and session reports.

---

## Module Responsibilities

* **Mentor List Management**:
  * Display overview of registered mentors with profile metadata, qualification, area of expertise, verification status, operational status, rating, and session count.
  * Tab-based status filtering (`All`, `Active`, `To verify`, `Suspended`).
  * Search mentors by name, qualification, or area of expertise.
  * Dual-mode data presentation: responsive data table on desktop/tablet and interactive card view on mobile.
  * Mentor quick preview via side drawer (`DrawerWrapper`) and operational status toggling/suspension via `ActionModal`.
  * Add new mentor drawer workflow and CSV export capability.

* **Mentor Profile & Permissions (Detail Screen)**:
  * Full mentor profile editing (`Display name`, `Qualification`, `Quote / motto`, `About me`, `Main area`).
  * Interactive specialisations manager with stadium pill toggle tags and new tag addition.
  * Short audio clips management (displaying title, duration, and delete/upload actions).
  * SheBloom verification management card with verification status pill (`VERIFIED` / `NOT VERIFIED`), verifier details, verified date, uploaded credential documents, and `Revoke verification` / `Mark as verified` actions.
  * Mentor operational permissions card with individual switches for `Profile editing allowed` and `Offering editing allowed`, linking to global mentor defaults in Settings.
  * Mentor operational status selector dropdown (`Active`, `To verify`, `Suspended`, `Deactivated`) and reported no-show metrics tracking (`1 report · S7`).
  * Responsive cross-device layout: 2-column asymmetric grid on desktop, full-width stacked cards on tablet & mobile, and centered full-width action button on mobile.

## Key Entities

* **MentorItem**:
  * `id`: string (e.g. `'men-1'`)
  * `name`: string (e.g. `'Dr Elisa Mestri'`)
  * `qualification`: string (e.g. `'Psychology · Mental coach'`)
  * `avatarInitials`: string (e.g. `'EM'`)
  * `area`: string (e.g. `'Relationships & Emotions'`)
  * `verification`: `'verified' | 'not_verified'`
  * `status`: `'active' | 'to_verify' | 'suspended' | 'deactivated'`
  * `rating`: number (optional, e.g. `4.9`)
  * `sessionCount`: number (optional, e.g. `128`)
  * `reportedNoShows`: number (optional, e.g. `1`)
  * `quote`: string (optional)
  * `about`: string (optional)
  * `specialisations`: string[] (e.g. `['Self-esteem', 'Relationships', 'Anxiety', 'Mindfulness']`)
  * `verifiedOn`: string (optional, formatted date `DD/MM/YYYY`)
  * `verifiedBy`: string (optional, admin name e.g. `'Giulia Ferri'`)
  * `documents`: string (optional, e.g. `"Psychologists' register no. 12345 · CV"`)
  * `profileEditingAllowed`: boolean (optional)
  * `offeringEditingAllowed`: boolean (optional)

* **AudioItem**:
  * `id`: string (e.g. `'aud-1'`)
  * `title`: string (e.g. `'3-minute breathing'`)
  * `duration`: string (e.g. `'03:12'`)

## API Endpoints

* **GET /backoffice/mentors**
  * Purpose: Fetch list of mentors with filtering, sorting, and pagination.
  * Authentication Required: Yes (Admin / Moderator)

* **GET /backoffice/mentors/:id**
  * Purpose: Fetch complete mentor profile, credentials, audio items, and permissions.
  * Authentication Required: Yes (Admin / Moderator)

* **PUT /backoffice/mentors/:id**
  * Purpose: Update mentor profile details, specialisations, and operational status.
  * Authentication Required: Yes (Admin / Moderator)

* **POST /backoffice/mentors**
  * Purpose: Onboard and invite a new mentor to She Bloom.
  * Authentication Required: Yes (Admin only)

* **POST /backoffice/mentors/:id/verification**
  * Purpose: Verify or revoke mentor's professional credentials and license documents.
  * Authentication Required: Yes (Admin only)

* **PUT /backoffice/mentors/:id/permissions**
  * Purpose: Update mentor editing permissions (`profileEditingAllowed`, `offeringEditingAllowed`).
  * Authentication Required: Yes (Admin only)

* **POST /backoffice/mentors/:id/audios**
  * Purpose: Upload a short intro/mindfulness audio track for the mentor.
  * Authentication Required: Yes (Admin / Moderator)

* **DELETE /backoffice/mentors/:id/audios/:audioId**
  * Purpose: Remove a mentor's audio track.
  * Authentication Required: Yes (Admin / Moderator)

## Database Tables

* **mentors**:
  * Purpose: Stores mentor core identity, biographical data, and area mappings.
  * Key Fields: `id`, `user_id`, `name`, `qualification`, `area_id`, `quote`, `about`, `rating`, `session_count`, `reported_no_shows`, `created_at`, `updated_at`

* **mentor_verifications**:
  * Purpose: Tracks verification status, auditor identity, and professional registration certificates.
  * Key Fields: `id`, `mentor_id`, `is_verified`, `verified_by`, `verified_at`, `license_no`, `documents_url`

* **mentor_permissions**:
  * Purpose: Governs whether mentor can self-publish profile or manage offerings directly.
  * Key Fields: `id`, `mentor_id`, `profile_editing_allowed`, `offering_editing_allowed`

* **mentor_specialisations**:
  * Purpose: Join table linking mentors to tagged specialisations.
  * Key Fields: `id`, `mentor_id`, `tag_name`

* **mentor_audios**:
  * Purpose: Short audio meditations or intros associated with a mentor.
  * Key Fields: `id`, `mentor_id`, `title`, `duration_seconds`, `file_url`, `created_at`

## Main Workflows

### 1. Mentor Exploration & Filtering Flow
1. Admin/Moderator navigates to `/mentors`.
2. Mentors are displayed with summary statistics, searchable by keyword and filterable by status tabs (`All`, `Active`, `To verify`, `Suspended`).
3. User can click a table row or action icon to open quick details drawer or navigate to full profile editing.

### 2. Mentor Profile Editing Flow
1. Admin selects a mentor to view `/mentors/detail?id=<id>`.
2. Form loads mentor bio, motto, area, specialisations, and uploaded audios.
3. User edits fields, toggles specialisation chips, or uploads new audio snippets.
4. Clicking `Save` validates the data and updates the mentor profile.

### 3. Verification & Credential Review Flow
1. In the `SheBloom verification` card, Admin reviews the professional registry number and attached CV/license.
2. If valid, Admin toggles or retains `VERIFIED` status.
3. If credentials are under dispute or expired, Admin clicks `Revoke verification`, transitioning badge to `NOT VERIFIED`.

### 4. Permissions & Status Management Flow
1. Admin manages `Profile editing allowed` and `Offering editing allowed` toggle switches (styled with clean solid white circular thumbs per Figma specification).
2. Admin inspects reported no-show metrics (`X report · S7`) and changes account status via the dropdown (`Active`, `To verify`, `Suspended`, `Deactivated`).

## Security Considerations

* Only users with `Admin` or `Moderator` roles have access to the Mentor management module.
* Modifying mentor permissions (`profile_editing_allowed`, `offering_editing_allowed`) and credential verification status is strictly restricted to `Admin` users.
* All verification status changes and revocations are logged to the audit log with admin user metadata and timestamp.

## Important Business Rules

* **Design System Conformance**: Hex colors must not be hardcoded in application code; semantic CSS variables (`var(--brand-primary)`, `var(--status-violet-bg)`, `var(--border-default)`) must be used.
* **Verification Status**:
  * Unverified mentors can be onboarded in `to_verify` status before submitting regulatory board registration.
  * When verification is revoked, mentor profiles cannot publish updates without admin approval.
* **Responsive Parity**:
  * On Desktop: Right-hand cards follow an edge-to-edge space-between layout with right-aligned metadata.
  * On Tablet: Verification card renders structured left-aligned 2-column layout to prevent premature wrapping.
  * On Mobile: Action buttons expand to full width with centered text and icons.
