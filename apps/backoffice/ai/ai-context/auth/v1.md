# Module: Authentication & Access Screens (FE-SH-BO-ACC) - Version 1

## Module Overview

This module provides the complete frontend user authentication, access verification, and account onboarding interface for the She Bloom backoffice web application. It encapsulates all user access touchpoints including credential login, wrong credential error handling, two-factor authentication (2FA) verification, mandatory 2FA enrollment setup with QR codes, invitation acceptance with password creation, self-service password recovery, and automatic idle session timeout.

---

## Module Responsibilities

* Provide the responsive split-screen authentication container layout (`AuthLayout.tsx`) supporting Desktop 1440 brand panel and Mobile 390 top header banner with floating card.
* Standardize the authentication header typography (`AuthHeader.tsx`) using Playfair Display serif fonts and soft circular icon badges (`shieldCheck`, `key`, `mail`, `successCircle`).
* Implement the primary Login screen (`Login.tsx`) with email and password inputs, remember me option, credential validation states, and navigation links.
* Render interactive inline error states (`Login.tsx`) showing red input focus halos and remaining attempt counters before account lockout.
* Implement the 2FA Verification screen (`TwoFactor.tsx`) with a 6-digit responsive `PinInput`, auto-focus progression, recovery code fallback, and administrator reset assistance copy.
* Implement the 2FA Setup screen (`EnableTwoFactor.tsx`) with numbered step badges (1, 2, 3), QR code display, monospace secret key, one-click clipboard copy button, and role badge indicator.
* Implement the Invitation & Password Setup screen (`SetPassword.tsx`) with disabled invitee email, new password, confirm password, and an interactive password complexity checklist.
* Implement the Password Recovery flow (`RecoverPassword.tsx`) featuring link submission and the "Check your email" confirmation state with a brand pink outline "Back to login" button.
* Integrate the 30-minute idle session timeout mechanism (`useIdleTimeout.ts`) and inactivity modal (`ActionModal.tsx`).
* Maintain responsive styling without layout distortion or horizontal clipping across mobile (iPhone SE 375px), tablet portrait (712px), tablet landscape (820px), and desktop (1440px).

## API Endpoints

This frontend authentication module integrates with the following backend identity and access management endpoints:

* `POST /backoffice/auth/login`
  * Submits email and password credentials for initial validation
  * Authentication Required: No
  * Response: Access token, user profile, or remaining attempts counter

* `POST /backoffice/auth/2fa/verify`
  * Submits 6-digit TOTP code to complete login session
  * Authentication Required: Temporary 2FA token
  * Response: Full backoffice access token and session cookie

* `POST /backoffice/auth/2fa/setup`
  * Confirms 2FA setup with initial 6-digit code and activates 2FA for the account
  * Authentication Required: Temporary token
  * Response: Confirmation status and recovery backup codes

* `POST /backoffice/auth/password/recover`
  * Dispatches time-limited (30 min) password reset link to user email
  * Authentication Required: No
  * Response: Generic success status to prevent email enumeration

* `POST /backoffice/auth/password/set`
  * Sets password using an invitation or recovery token
  * Authentication Required: Token in query/payload
  * Response: Success status

* `POST /backoffice/auth/logout`
  * Invalidates user session and revokes access token
  * Authentication Required: Yes

## Database Tables

Frontend authentication views consume and manage state corresponding to backend user models:

* **users / backoffice_users:**
  * Stores administrator, moderator, and mentor records
  * Key Fields: `id`, `email`, `password_hash`, `role`, `status`, `failed_attempts`, `locked_until`, `two_factor_enabled`, `two_factor_secret`
* **password_resets:**
  * Stores hashed password reset tokens and validity timestamps
  * Key Fields: `id`, `user_id`, `token_hash`, `expires_at`, `used_at`
* **invitations:**
  * Tracks pending backoffice mentor/admin invitations
  * Key Fields: `id`, `email`, `role`, `token_hash`, `expires_at`, `accepted_at`
* **audit_logs:**
  * Records security events (login success, login failure, 2FA prompt, password changes, session timeouts)
  * Key Fields: `id`, `user_id`, `action`, `ip_address`, `user_agent`, `created_at`

## Main Workflows

### 1. Standard Login Workflow (RF-BO-ACC-01, RF-BO-ACC-02)
1. User enters email and password on the login screen.
2. If credentials match and 2FA is not required, user receives JWT token and is redirected to the backoffice dashboard.
3. If credentials fail, system renders the error state with red input halos and updates the remaining attempts counter (e.g., *"Attempts left: 2"*).

### 2. Two-Factor Authentication Workflow (RF-BO-ACC-03)
1. User enters valid credentials for an account requiring 2FA.
2. System transitions user to the 2FA verification screen (`?screen=2fa`).
3. User enters 6-digit TOTP code generated by Google Authenticator, Microsoft Authenticator, or 1Password.
4. Auto-focus advances smoothly across the 6 boxes; submitting validates the code and issues the session.
5. If user lacks device access, clicking *"Use a recovery code"* offers alternate verification.

### 3. Mandatory 2FA Enrollment Workflow (RF-BO-ACC-03, RF-BO-SET-05)
1. First-time Admin/Mentor logins require mandatory 2FA enrollment.
2. System presents 3-step setup guide with QR code and secret key.
3. User scans QR or copies key to authenticator app.
4. User enters 6-digit confirmation code and clicks *"Enable and continue"*.

### 4. Invitation & Password Setup Workflow (RF-BO-ACC-01, RF-BO-ACC-06)
1. New team member receives invitation email and clicks link to backoffice.
2. System renders welcome screen displaying disabled invitee email.
3. User enters new password; real-time checklist visually turns green as criteria (10+ characters, uppercase, number, special char) are satisfied.
4. User confirms password and submits to activate account.

### 5. Password Recovery Workflow (RF-BO-ACC-04)
1. User clicks *"Forgot password?"* from the login screen.
2. User enters registered email and clicks *"Send link"*.
3. System transitions to the "Check your email" confirmation screen with brand pink outline button to return to login.

### 6. Inactivity Session Timeout Workflow (RF-BO-ACC-05)
1. User remains idle across window events for 30 consecutive minutes.
2. `useIdleTimeout` triggers the `Session expired` overlay modal.
3. Background is dimmed with backdrop blur; clicking *"Log in again"* clears local credentials and returns to the sign-in screen.

## Security Considerations

* Passwords are never logged or stored in client-side state beyond form submission lifecycles.
* Password fields use standard browser `autocomplete="current-password"` and `autocomplete="new-password"` attributes.
* Password reset confirmation displays generic success feedback to prevent account/email harvesting.
* PinInput enforces strictly numeric input types (`type="number"`).
* Session inactivity automatically closes authenticated sessions after 30 minutes without user interaction.
* Remaining attempts warning mitigates brute-force attacks by alerting users before account lockout occurs.

## Important Business Rules

* **Single Source of Truth:** All authentication pages strictly inherit design tokens from `theme.ts` (fonts, radii, colors, and shadows).
* **Zero Hardcoding Rule:** No raw hex codes or direct font strings in JSX; CSS custom properties (`var(--...)`) are strictly used.
* **Password Complexity:** Minimum 10 characters, at least 1 uppercase letter, at least 1 number, and at least 1 special character.
* **Role-Based 2FA:** Enabled by default for all backoffice roles (Admin, Moderator, Mentor).
* **Responsive Breakpoints:**
  * Desktop (≥ 1200px): Split-screen with 44% brand panel on the left and floating card on the right.
  * Tablet (768px – 1199px): Proportional split-screen with scaled brand panel.
  * Mobile (< 768px): Single-column layout with compact top banner and centered floating white card (`border-radius: 16px`, shadow).
  * Small mobile (≤ 420px): PinInput dynamically scales from 48px to 38px width to eliminate horizontal overflow.
