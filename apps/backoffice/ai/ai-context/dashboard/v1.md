# Module: Admin Dashboard (FE-SH-BO-DASH) - Version 1

## Module Overview

This module provides the central command center and administrative operational overview for the She Bloom backoffice web application. It delivers high-level operational visibility across platform health, pending administrative tasks, key performance indicators (KPIs), upcoming bookings and mentor sessions, subscriber growth analytics, and content publication schedules.

---

## Module Responsibilities

* Render the primary administrative dashboard view (`AdminDashboard.tsx`) within the authenticated application layout (`AppLayout.tsx`).
* Display high-priority operational alert banners (e.g., active SOS alerts) with quick-action links.
* Provide an administrative action bar allowing one-click data export, CSV report downloads, and quick content creation.
* Visualize high-level platform KPI metrics with trends, period comparisons, and directional indicators.
* Display the today's bookings schedule table with mentor, user, service, and live status badges (`Completed`, `In Progress`, `Upcoming`, `Cancelled`).
* Present a subscriber growth bar chart visualization tracking monthly active Bloom Club subscriptions.
* Manage the "To handle" actionable queue prioritizing moderation requests, unassigned Q&As, missing session notes, call link verifications, and mentor verifications with counter badges.
* Display the "Scheduled content" editorial calendar preview showing upcoming posts, publication dates, and publication status badges.
* Ensure full responsiveness across desktop (1440px+), tablet, and mobile viewport widths without layout shifting or horizontal clipping.

---

## Key Entities

* **AdminDashboard (`src/pages/Dashboard/AdminDashboard.tsx`):** Core screen component organizing KPI cards, alert banners, tables, visualizations, and actionable queues.
* **KPI Card Metrics (`DashboardKPI`):** Data structure capturing key numbers (e.g., Active Users, Bloom Club Subscribers, Total Bookings, Pending SOS Alerts) with change metrics and timeframes.
* **Booking Schedule Item (`BookingRow`):** Data entity representing scheduled sessions with timestamp, client name & email, mentor assignment, service type, and session status (`success`, `warning`, `info`, `danger`).
* **Subscription Month Data (`SubscriptionMonth`):** Monthly metric entity tracking subscriber volume across historical and current billing periods.
* **To-Handle Item (`ToHandleItem`):** Actionable administrative backlog item with category title, count, soft-violet icon wrapper, and status-colored counter pill badge.
* **Scheduled Content Item (`ScheduledContentItem`):** Editorial queue item with content title, scheduled publish timestamp, type indicator, and status badge.
* **StatusBadge (`src/components/StatusBadge/StatusBadge.tsx`):** Unified badge component rendering semantic statuses with circular dot indicator.
* **CounterBadge (`src/components/CounterBadge/CounterBadge.tsx`):** Compact pill badge rendering numeric counts with danger, brand, or neutral color schemes.
* **AppIcon (`src/components/AppIcon/AppIcon.tsx`):** Dynamic Tabler icon wrapper standardizing icon sizing, stroke widths, and colors across the dashboard.

## API Endpoints

This frontend module consumes the following administrative backoffice REST endpoints:

* `GET /backoffice/dashboard/kpis`
  * Fetches aggregated KPI metrics (Active Users, Club Subscribers, Total Bookings, SOS Alerts) with period-over-period delta percentages
  * Authentication Required: Yes

* `GET /backoffice/dashboard/alerts`
  * Retrieves active critical platform alerts and emergency SOS triggers requiring immediate administrative attention
  * Authentication Required: Yes

* `GET /backoffice/dashboard/bookings/today`
  * Retrieves today's scheduled mentor sessions, client details, and call connection status
  * Authentication Required: Yes

* `GET /backoffice/dashboard/analytics/subscribers`
  * Retrieves 6-month historical subscriber growth counts for the dashboard bar chart
  * Authentication Required: Yes

* `GET /backoffice/dashboard/to-handle`
  * Retrieves pending backlog task counters (reports to moderate, unassigned Q&A, missing session notes, missing call links, unverified mentors)
  * Authentication Required: Yes

* `GET /backoffice/dashboard/content/scheduled`
  * Retrieves upcoming scheduled daily content and editorial posts
  * Authentication Required: Yes

* `POST /backoffice/dashboard/export`
  * Triggers generation and asynchronous export of aggregated platform activity reports
  * Authentication Required: Yes

* `GET /backoffice/bookings/export-csv`
  * Generates and downloads a CSV export of filtered bookings data
  * Authentication Required: Yes

## Database Tables

This module presents aggregated data derived from the following core platform tables:

* **users**
  * Tracks registered platform users, subscriber status, and verification states
  * Key Fields: `id`, `name`, `email`, `role`, `status`, `created_at`

* **bookings**
  * Stores mentor-client consultation bookings and schedule details
  * Key Fields: `id`, `user_id`, `mentor_id`, `service_type`, `scheduled_at`, `call_link`, `status`

* **subscriptions**
  * Tracks active and historical Bloom Club memberships
  * Key Fields: `id`, `user_id`, `plan_id`, `status`, `current_period_start`, `current_period_end`

* **reports**
  * Captures user-submitted content reports and moderation tickets
  * Key Fields: `id`, `reporter_id`, `target_type`, `target_id`, `reason`, `status`, `created_at`

* **mentor_profiles**
  * Stores mentor applications and credential verification states
  * Key Fields: `id`, `user_id`, `verification_status`, `specialties`, `verified_at`

* **scheduled_content**
  * Manages daily editorial content calendar and automated publishing
  * Key Fields: `id`, `title`, `content_type`, `publish_at`, `status`, `author_id`

* **sos_alerts**
  * Records emergency safety triggers requiring urgent administrator intervention
  * Key Fields: `id`, `user_id`, `triggered_at`, `resolved_at`, `status`

## Main Workflows

### 1. Dashboard Initialization & Metric Review Flow
1. Administrator navigates to the Backoffice root or `/dashboard`.
2. System validates authentication token and administrative permissions.
3. Dashboard fetches KPI metrics, today's schedule, subscriber trends, and pending tasks in parallel.
4. Alerts banner is rendered if unhandled SOS alerts exist.

### 2. Operational Action Queue Flow ("To handle")
1. Administrator reviews pending item counts in the "To handle" card.
2. Clicking any row (e.g., "Reports to moderate" or "Mentors to verify") triggers navigation with preset filters to the corresponding administrative module.
3. Upon resolution in the target module, item counter updates in real time.

### 3. Bookings Monitoring Flow
1. Administrator inspects today's upcoming session schedule.
2. Items with missing call links or pending status are surfaced with warning badges.
3. Administrator can export bookings CSV or navigate to full calendar view.

## Security Considerations

* Only authenticated users with backoffice administrative roles (`Super Admin`, `Admin`, `Support Lead`) can access this dashboard.
* Data export endpoints (`/backoffice/dashboard/export`, `/backoffice/bookings/export-csv`) require valid session bearer tokens with audit logging of the exporting administrator.
* Sensitive user personal details in the bookings table are limited to operational identifiers (name and contact email).

---

## Important Business Rules

* "To handle" counters must aggregate only unresolved / unassigned tickets.
* Subscriptions chart highlights the current billing month distinctly from past completed periods.
* The emergency SOS alert banner must remain prominently visible at the top of the dashboard until dismissed or acknowledged by an administrator.
* Bookings schedule shows chronological sessions for the current day only.
